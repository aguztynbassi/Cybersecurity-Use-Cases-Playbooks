# Network Trace Capture Initiated with Netsh

## Description
Alert generated by the `Network Trace Capture Initiated with Netsh` detection. Detects the use of the `netsh.exe` utility with the `trace start` command to initiate a network packet capture. This built-in Windows utility, often used for diagnostics, can be abused by adversaries to monitor network traffic, collect sensitive data, or prepare for data exfiltration. The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to network device (firewall, router, switch, or IDS/IPS sensor), enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Logic
The detection is triggered by the `Network Trace Capture Initiated with Netsh` rule. The prioritization logic should consider severity, asset criticality, event recurrence, network source/destination, involved identity, platform, and correlated activity in supporting data sources.

Patterns or conditions to validate:

- Exact match of the detection name/signature with this use case.
- Severity equal to or above the SOC-defined threshold.
- Production, critical, publicly exposed, or sensitive-data asset.
- IP address, domain, user, process, or resource not recognized by the asset/account owner.
- Logs or telemetry from the supporting data sources occurring close to the first or last observed event.
- Sensitive changes following the event, such as permission changes, new persistence, credential use, logging changes, public exposure, command execution, or data access.

## Investigation

Mandatory 5W Questions:

- **Who:** Which user, host, service account, process, or external actor is involved?
- **What:** What action was observed, and what asset was affected? Was there access, execution, a configuration change, network communication, or an authentication attempt?
- **When:** When did the first and last observations occur? Did the activity take place outside expected business hours or near another change?

## Evidence for Determination

### False Positives

- The `Network Trace Capture Initiated with Netsh` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- A legitimate user forgot their password or mistyped credentials; failed attempts stop after a normal self-correction.
- An approved credential-management tool or migration script is reading/validating credentials as part of its documented function.
- A legitimate administrative, monitoring, or inventory tool performs the same enumeration as part of its normal, approved function.
- A new, approved automation or audit process is running for the first time and has not yet been accounted for.

### True Positives

- This built-in Windows utility, often used for diagnostics, can be abused by adversaries to monitor network traffic, collect sensitive data, or prepare for data exfiltration.
- The attempt pattern (volume, source diversity, targeted usernames) is inconsistent with normal user behavior and matches brute-force, spraying, or credential-dumping tradecraft.
- A successful authentication follows a string of failures, or succeeds from a source/location with no history for this account.
- The credential material or technique matches a known credential-access tool.
- The enumeration is performed by an identity or process with no legitimate reason to need this information.
- It follows another compromise indicator on the same host or account.

### True Negatives

- The pattern is confirmed to be normal user error or an approved automated process.
- The activity is confirmed to be an approved, scheduled audit or inventory process.

### False Negatives

- The attacker already possesses valid, previously-stolen credentials and succeeds on the first attempt, leaving no failed-attempt pattern to detect.
- Credential material is harvested through a channel this detection does not monitor (e.g., a phishing page hosted outside the organization).
- The attacker already has the information from a prior reconnaissance phase or from an external source, so no new enumeration activity is generated.
- Discovery is performed through an API or method this detection does not cover.

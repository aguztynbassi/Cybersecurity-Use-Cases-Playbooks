# Infrastructure Provisioning Detected

## Description
Alert generated by the `Infrastructure Provisioning Detected` detection. New cloud infrastructure provisioning has been detected, which could indicate resource development for malicious activities. The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to cloud (IaaS) resource or account, enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Logic
The detection is triggered by the `Infrastructure Provisioning Detected` rule. The prioritization logic should consider severity, asset criticality, event recurrence, network source/destination, involved identity, platform, and correlated activity in supporting data sources.

Patterns or conditions to validate:

- Exact match of the detection name/signature with this use case.
- Severity equal to or above the SOC-defined threshold.
- Production, critical, publicly exposed, or sensitive-data asset.
- IP address, domain, user, process, or resource not recognized by the asset/account owner.
- Logs or telemetry from the supporting data sources occurring close to the first or last observed event.
- Sensitive changes following the event, such as permission changes, new persistence, credential use, logging changes, public exposure, command execution, or data access.

## MITRE ATT&CK

- T1583.003 - Virtual Private Server (Resource Development)

## Threat
- **Primary Threat:** Resource Development.
- **Family or Mechanism:** Infrastructure Provisioning Detected.
- New cloud infrastructure provisioning has been detected, which could indicate resource development for malicious activities. The analyst should consider credential compromise, malware infection, policy violation, misconfiguration, or legitimate administrative activity depending on the technical context of the alert.
- **Data Sources:** cloud provider audit logs (e.g. AWS CloudTrail), VPC Flow Logs, endpoint/EDR telemetry on cloud instances.

## Investigation Sources
- **Detection Details:** rule/detection name, severity, affected host/user/resource, first and last observed time, recurrence count.
- **Identity and Access Logs:** authentication events, session/token details, source IP, user agent, and any related administrative actions.
- **Network Logs:** source/destination IP, port, protocol, country, ASN, and transferred bytes where applicable to this detection.
- **Asset/Resource Configuration:** owner, criticality, exposure, patch level, and any security-control configuration relevant to the finding.
- Operational validation with the resource owner, platform team, or application owner to confirm whether the activity was expected.

## Investigation

Mandatory 5W Questions:

- **Who:** Which user, host, service account, process, or external actor is involved?
- **What:** What action was observed, and what asset was affected? Was there access, execution, a configuration change, network communication, or an authentication attempt?
- **When:** When did the first and last observations occur? Did the activity take place outside expected business hours or near another change?
- **Where:** From which host, IP address, country, ASN, or platform did the activity originate?
- **Why:** Is there an operational justification, approved automation, authorized testing activity, or planned change that explains the event?

## Detailed Checklist for Analysts Reviewing the Alert

- Detection/rule name, severity, affected host, user, or resource, and the platform/category it was raised on.
- Involved identity: username, service account, process owner, or the external source identified in the alert.
- Source and destination details available for this alert (IP, domain, port, protocol, country, ASN) where applicable.
- First and last observed event, frequency, and recurrence within the analysis period.
- Sensitive follow-on actions, such as privilege changes, new persistence mechanisms, log tampering, or data access.
- Relationship with other alerts, EDR detections, SIEM correlations, or existing tickets for the same host/user.
- Confirmation with the owner regarding expected activity, approved automation, authorized testing, or unknown behavior.
- Specific fields referenced by this detection's own alert template:
  - `Timestamp` - The timestamp of the infrastructure provisioning event.
  - `user` - The user or entity that performed the provisioning.
  - `resource_id` - The unique ID of the provisioned resource.
  - `resource_type` - The type of resource provisioned (e.g., 'ec2_instance', 'vm').
  - `region` - The cloud region where the resource was provisioned.
  - `source_ip` - The source IP address from which the activity originated.
  - `activity` - The activity that triggered the rule (e.g., 'provision').

## Evidence for Determination

### False Positives

- The `Infrastructure Provisioning Detected` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- The activity reflects the organization's own, legitimate infrastructure or domain/certificate procurement.
- A security or threat-intelligence team intentionally registered look-alike infrastructure for defensive research.

### True Positives

- New cloud infrastructure provisioning has been detected, which could indicate resource development for malicious activities.
- The newly acquired infrastructure (domain, VPS, certificate) has no legitimate business relationship with the organization and later correlates with phishing or C2 activity observed elsewhere.
- Threat-intelligence enrichment links the infrastructure to a known actor or campaign.

### True Negatives

- The resource is confirmed as an approved, internally procured asset.

### False Negatives

- The actor acquires infrastructure through a reseller, proxy, or compromised third-party account that doesn't surface in standard registration/threat-intel feeds.

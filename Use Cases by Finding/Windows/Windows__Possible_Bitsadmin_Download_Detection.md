# Defense Evasion: BITSAdmin Download Activity

## Description
Alert generated by the `Defense Evasion: BITSAdmin Download Activity` detection. Detects the use of the bitsadmin.exe utility to create transfer jobs or directly download files from external sources. Attackers abuse BITS to asynchronously download malicious payloads, taking advantage of this traffic typically being ignored by perimeter defenses and its ability to maintain persistence by resuming downloads after system reboots. The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to Windows host, enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Logic
The detection is triggered by the `Defense Evasion: BITSAdmin Download Activity` rule. The prioritization logic should consider severity, asset criticality, event recurrence, network source/destination, involved identity, platform, and correlated activity in supporting data sources.

Patterns or conditions to validate:

- Exact match of the detection name/signature with this use case.
- Severity equal to or above the SOC-defined threshold.
- Production, critical, publicly exposed, or sensitive-data asset.
- IP address, domain, user, process, or resource not recognized by the asset/account owner.
- Logs or telemetry from the supporting data sources occurring close to the first or last observed event.
- Sensitive changes following the event, such as permission changes, new persistence, credential use, logging changes, public exposure, command execution, or data access.

## Investigation

Mandatory 5W Questions:

- **Who:** Which user, host, service account, process, or external actor is involved?
- **What:** What action was observed, and what asset was affected? Was there access, execution, a configuration change, network communication, or an authentication attempt?
- **When:** When did the first and last observations occur? Did the activity take place outside expected business hours or near another change?
- **Where:** From which host, IP address, country, ASN, or platform did the activity originate?
- **Why:** Is there an operational justification, approved automation, authorized testing activity, or planned change that explains the event?

## Evidence for Determination

### False Positives

- The `Defense Evasion: BITSAdmin Download Activity` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- A legitimate administrator, script, or scheduled task executed the command/binary as part of approved, documented operations.
- A security or monitoring tool itself performs an action that matches this execution pattern by design.
- A legitimate software installer, IT management tool, or approved automation created the persistence mechanism as part of its normal function.
- An administrator intentionally configured the mechanism (service, scheduled task, startup entry) for a documented operational reason.

### True Positives

- Attackers abuse BITS to asynchronously download malicious payloads, taking advantage of this traffic typically being ignored by perimeter defenses and its ability to maintain persistence by resuming downloads after system reboots.
- The executing process, command line, or binary has no legitimate reason to run in this context and matches known attacker tradecraft.
- Execution is followed by further suspicious activity (network connections, new files, privilege changes) on the same host.
- The owner of the host/account cannot account for the execution when asked.
- The persistence mechanism points to an unfamiliar binary, script, or location with no legitimate business purpose.
- The mechanism was created shortly after another suspicious event on the same host (new login, exploitation, suspicious download).

### True Negatives

- The execution is confirmed to be part of an approved script, deployment, or administrative task.
- The change is tied to an approved deployment or administrative action.

### False Negatives

- The payload executes through a technique or LOLBin not yet covered by this detection's specific logic.
- The malicious code runs entirely in memory or is obfuscated enough to avoid matching the detection's pattern.
- The persistence mechanism is deliberately disguised to resemble a legitimate, commonly-seen entry.
- Persistence is established through a technique this detection does not specifically cover.

# Renamed PsExec Detected

## Description
Alert generated by the `Renamed PsExec Detected` detection. Detection of a renamed PsExec binary. PsExec is a legitimate utility but is often abused by attackers for lateral movement and remote code execution. Adversaries may rename it to evade detection by security software. This detection looks for a known hash or file size of PsExec when executed under a different name. The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to Windows host, enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Logic
The detection is triggered by the `Renamed PsExec Detected` rule. The prioritization logic should consider severity, asset criticality, event recurrence, network source/destination, involved identity, platform, and correlated activity in supporting data sources.

Patterns or conditions to validate:

- Exact match of the detection name/signature with this use case.
- Severity equal to or above the SOC-defined threshold.
- Production, critical, publicly exposed, or sensitive-data asset.
- IP address, domain, user, process, or resource not recognized by the asset/account owner.
- Logs or telemetry from the supporting data sources occurring close to the first or last observed event.
- Sensitive changes following the event, such as permission changes, new persistence, credential use, logging changes, public exposure, command execution, or data access.

## Evidence for Determination

### False Positives

- The `Renamed PsExec Detected` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- An approved IT operations or configuration-management tool legitimately connects to or executes commands on other hosts as part of its documented function.
- A legitimate debugging, monitoring, or anti-tampering tool triggered the same low-level behavior this detection watches for.
- An approved administrative action (patching, reconfiguration) incidentally matches the detection's pattern.

### True Positives

- This detection looks for a known hash or file size of PsExec when executed under a different name.
- The connecting identity or host has no legitimate operational relationship with the target, and the action follows a known lateral-movement technique.
- The same technique is observed spreading to multiple hosts in a short window.
- It follows a credential-theft or initial-access indicator on the originating host.
- The activity has no legitimate operational explanation and matches a known defense-evasion or anti-analysis technique.
- It coincides with other indicators of compromise on the same host or account.

### True Negatives

- The activity matches an approved administrative or orchestration tool's documented behavior.
- The behavior is confirmed to come from an approved, documented tool or maintenance action.

### False Negatives

- The attacker moves laterally using already-trusted, legitimate administrative channels that closely mimic normal IT operations.
- The adversary uses a technique variant or tooling this detection's specific logic does not yet cover.
- The evasive action is brief enough that it completes before generating a strong enough signal.

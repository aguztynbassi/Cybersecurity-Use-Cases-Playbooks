# Windows: Reverse RDP Lateral Movement via tsclient

## Description
Alert generated by the `Windows: Reverse RDP Lateral Movement via tsclient` detection. Detects attempts to write files to the Startup folder of a remote machine through an active RDP session. The attacker uses the 'mstsc.exe' process and the 'tsclient' share to place malicious artifacts on the administrator's machine that connected, enabling lateral movement from a compromised server toward the originating workstation. The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to Windows host, enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Logic
The detection is triggered by the `Windows: Reverse RDP Lateral Movement via tsclient` rule. The prioritization logic should consider severity, asset criticality, event recurrence, network source/destination, involved identity, platform, and correlated activity in supporting data sources.

Patterns or conditions to validate:

- Exact match of the detection name/signature with this use case.
- Severity equal to or above the SOC-defined threshold.
- Production, critical, publicly exposed, or sensitive-data asset.
- IP address, domain, user, process, or resource not recognized by the asset/account owner.
- Logs or telemetry from the supporting data sources occurring close to the first or last observed event.
- Sensitive changes following the event, such as permission changes, new persistence, credential use, logging changes, public exposure, command execution, or data access.

## Evidence for Determination

### False Positives

- The `Windows: Reverse RDP Lateral Movement via tsclient` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- An approved IT operations or configuration-management tool legitimately connects to or executes commands on other hosts as part of its documented function.
- A legitimate software installer, IT management tool, or approved automation created the persistence mechanism as part of its normal function.
- An administrator intentionally configured the mechanism (service, scheduled task, startup entry) for a documented operational reason.

### True Positives

- The attacker uses the 'mstsc.exe' process and the 'tsclient' share to place malicious artifacts on the administrator's machine that connected, enabling lateral movement from a compromised server toward the originating workstation.
- The connecting identity or host has no legitimate operational relationship with the target, and the action follows a known lateral-movement technique.
- The same technique is observed spreading to multiple hosts in a short window.
- It follows a credential-theft or initial-access indicator on the originating host.
- The persistence mechanism points to an unfamiliar binary, script, or location with no legitimate business purpose.
- The mechanism was created shortly after another suspicious event on the same host (new login, exploitation, suspicious download).

### True Negatives

- The activity matches an approved administrative or orchestration tool's documented behavior.
- The change is tied to an approved deployment or administrative action.

### False Negatives

- The attacker moves laterally using already-trusted, legitimate administrative channels that closely mimic normal IT operations.
- The persistence mechanism is deliberately disguised to resemble a legitimate, commonly-seen entry.
- Persistence is established through a technique this detection does not specifically cover.

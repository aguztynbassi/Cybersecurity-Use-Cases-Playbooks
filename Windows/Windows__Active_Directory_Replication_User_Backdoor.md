# Active Directory Replication User Backdoor (DCSync Permissions)

## Description
Alert generated by the `Active Directory Replication User Backdoor (DCSync Permissions)` detection. Detects a potential Active Directory backdoor where the `nTSecurityDescriptor` attribute of a domain object is modified to grant Active Directory replication permissions to a user or computer account. This modification enables the granted account to perform DCSync attacks, allowing an adversary to extract credential hashes for all domain users. The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to Windows host, enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Evidence for Determination

### False Positives

- The `Active Directory Replication User Backdoor (DCSync Permissions)` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- A legitimate user forgot their password or mistyped credentials; failed attempts stop after a normal self-correction.
- An approved credential-management tool or migration script is reading/validating credentials as part of its documented function.
- A platform or security administrator intentionally disabled or reconfigured the control as part of an approved maintenance or migration task, with change records on file.

### True Positives

- This modification enables the granted account to perform DCSync attacks, allowing an adversary to extract credential hashes for all domain users.
- The attempt pattern (volume, source diversity, targeted usernames) is inconsistent with normal user behavior and matches brute-force, spraying, or credential-dumping tradecraft.
- A successful authentication follows a string of failures, or succeeds from a source/location with no history for this account.
- The credential material or technique matches a known credential-access tool.
- A security control (logging, AV/EDR, firewall rule, audit policy) was disabled or weakened by an identity with no administrative justification for managing it.
- The change occurs immediately before or after other suspicious activity that the disabled control would otherwise have captured.

### True Negatives

- The pattern is confirmed to be normal user error or an approved automated process.
- The change is tied to an approved, documented administrative action.

### False Negatives

- The attacker already possesses valid, previously-stolen credentials and succeeds on the first attempt, leaving no failed-attempt pattern to detect.
- Credential material is harvested through a channel this detection does not monitor (e.g., a phishing page hosted outside the organization).
- The attacker impairs a different control not covered by this specific detection, or avoids touching monitored settings entirely.
- The control is disabled only momentarily, in a window too short to generate a reliable signal.

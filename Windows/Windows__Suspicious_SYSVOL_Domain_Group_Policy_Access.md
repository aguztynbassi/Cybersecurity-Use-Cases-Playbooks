# Suspicious SYSVOL Domain Group Policy Access

## Description
Alert generated by the `Suspicious SYSVOL Domain Group Policy Access` detection. Detection of access to Domain Group Policies stored in the SYSVOL folder. Adversaries may access these policies to discover user passwords or other sensitive information, which is a common credential access technique. The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to Windows host, enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Logic
The detection is triggered by the `Suspicious SYSVOL Domain Group Policy Access` rule. The prioritization logic should consider severity, asset criticality, event recurrence, network source/destination, involved identity, platform, and correlated activity in supporting data sources.

Patterns or conditions to validate:

- Exact match of the detection name/signature with this use case.
- Severity equal to or above the SOC-defined threshold.
- Production, critical, publicly exposed, or sensitive-data asset.
- IP address, domain, user, process, or resource not recognized by the asset/account owner.
- Logs or telemetry from the supporting data sources occurring close to the first or last observed event.
- Sensitive changes following the event, such as permission changes, new persistence, credential use, logging changes, public exposure, command execution, or data access.

## Evidence for Determination

### False Positives

- The `Suspicious SYSVOL Domain Group Policy Access` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- A legitimate user forgot their password or mistyped credentials; failed attempts stop after a normal self-correction.
- An approved credential-management tool or migration script is reading/validating credentials as part of its documented function.

### True Positives

- Adversaries may access these policies to discover user passwords or other sensitive information, which is a common credential access technique.
- The attempt pattern (volume, source diversity, targeted usernames) is inconsistent with normal user behavior and matches brute-force, spraying, or credential-dumping tradecraft.
- A successful authentication follows a string of failures, or succeeds from a source/location with no history for this account.
- The credential material or technique matches a known credential-access tool.

### True Negatives

- The pattern is confirmed to be normal user error or an approved automated process.

### False Negatives

- The attacker already possesses valid, previously-stolen credentials and succeeds on the first attempt, leaving no failed-attempt pattern to detect.
- Credential material is harvested through a channel this detection does not monitor (e.g., a phishing page hosted outside the organization).

# MiniNt Registry Key Creation/Modification Detected (Event Log Evasion)

## Description
Alert generated by the `MiniNt Registry Key Creation/Modification Detected (Event Log Evasion)` detection. Critical defense evasion detected: Creation or modification of the 'HKLM\SYSTEM\CurrentControlSet\Control\MiniNt' registry key, which can disable Windows Event Logging after reboot. The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to Windows host, enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Logic
The detection is triggered by the `MiniNt Registry Key Creation/Modification Detected (Event Log Evasion)` rule. The prioritization logic should consider severity, asset criticality, event recurrence, network source/destination, involved identity, platform, and correlated activity in supporting data sources.

Patterns or conditions to validate:

- Exact match of the detection name/signature with this use case.
- Severity equal to or above the SOC-defined threshold.
- Production, critical, publicly exposed, or sensitive-data asset.
- IP address, domain, user, process, or resource not recognized by the asset/account owner.
- Logs or telemetry from the supporting data sources occurring close to the first or last observed event.
- Sensitive changes following the event, such as permission changes, new persistence, credential use, logging changes, public exposure, command execution, or data access.

## Threat
- **Primary Threat:** Defense Impairment.
- **Family or Mechanism:** MiniNt Registry Key Creation/Modification Detected (Event Log Evasion).
- Critical defense evasion detected: Creation or modification of the 'HKLM\SYSTEM\CurrentControlSet\Control\MiniNt' registry key, which can disable Windows Event Logging after reboot. The analyst should consider credential compromise, malware infection, policy violation, misconfiguration, or legitimate administrative activity depending on the technical context of the alert.
- **Data Sources:** Windows Security/System Event Logs, Sysmon, EDR telemetry, PowerShell script-block logging.

## Investigation Sources
- **Detection Details:** rule/detection name, severity, affected host/user/resource, first and last observed time, recurrence count.
- **Identity and Access Logs:** authentication events, session/token details, source IP, user agent, and any related administrative actions.
- **Network Logs:** source/destination IP, port, protocol, country, ASN, and transferred bytes where applicable to this detection.
- **Asset/Resource Configuration:** owner, criticality, exposure, patch level, and any security-control configuration relevant to the finding.
- Operational validation with the resource owner, platform team, or application owner to confirm whether the activity was expected.

## Investigation

Mandatory 5W Questions:

- **Who:** Which user, host, service account, process, or external actor is involved?
- **What:** What action was observed, and what asset was affected? Was there access, execution, a configuration change, network communication, or an authentication attempt?
- **When:** When did the first and last observations occur? Did the activity take place outside expected business hours or near another change?
- **Where:** From which host, IP address, country, ASN, or platform did the activity originate?
- **Why:** Is there an operational justification, approved automation, authorized testing activity, or planned change that explains the event?

## Detailed Checklist for Analysts Reviewing the Alert

- Involved identity: username, service account, process owner, or the external source identified in the alert.

## Evidence for Determination

### False Positives

- The `MiniNt Registry Key Creation/Modification Detected (Event Log Evasion)` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- A platform or security administrator intentionally disabled or reconfigured the control as part of an approved maintenance or migration task, with change records on file.

### True Positives

- Critical defense evasion detected: Creation or modification of the 'HKLM\SYSTEM\CurrentControlSet\Control\MiniNt' registry key, which can disable Windows Event Logging after reboot.
- A security control (logging, AV/EDR, firewall rule, audit policy) was disabled or weakened by an identity with no administrative justification for managing it.
- The change occurs immediately before or after other suspicious activity that the disabled control would otherwise have captured.
- No change ticket or administrator acknowledges the modification.

### True Negatives

- The change is tied to an approved, documented administrative action.

### False Negatives

- The attacker impairs a different control not covered by this specific detection, or avoids touching monitored settings entirely.
- The control is disabled only momentarily, in a window too short to generate a reliable signal.

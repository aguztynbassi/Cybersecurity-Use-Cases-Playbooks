# CMSTP.exe Signed Binary Proxy Execution

## Description
Alert generated by the `CMSTP.exe Signed Binary Proxy Execution` detection. Detects the abuse of `CMSTP.exe` (Connection Manager Profile Installer), a legitimate signed Windows binary. Adversaries can leverage `CMSTP.exe` for indirect command execution and defense evasion by using it to install a malicious `.INF` file. This technique, part of "Signed Binary Proxy Execution," allows the execution of arbitrary commands or DLLs, often bypassing application whitelisting and potentially User Account Control (UAC). The alert must be reviewed by the SOC to validate its legitimacy, scope, affected asset, and potential impact.

## Objective
Detect and prioritize potential malicious, anomalous, or unauthorized activity related to Windows host, enabling the SOC to initiate a structured investigation, reduce operational risk, and activate containment procedures when indicators of compromise are identified.

## Logic
The detection is triggered by the `CMSTP.exe Signed Binary Proxy Execution` rule. The prioritization logic should consider severity, asset criticality, event recurrence, network source/destination, involved identity, platform, and correlated activity in supporting data sources.

Patterns or conditions to validate:

- Exact match of the detection name/signature with this use case.
- Severity equal to or above the SOC-defined threshold.
- Production, critical, publicly exposed, or sensitive-data asset.
- IP address, domain, user, process, or resource not recognized by the asset/account owner.
- Logs or telemetry from the supporting data sources occurring close to the first or last observed event.
- Sensitive changes following the event, such as permission changes, new persistence, credential use, logging changes, public exposure, command execution, or data access.

## Evidence for Determination

### False Positives

- The `CMSTP.exe Signed Binary Proxy Execution` rule has not yet been tuned to this environment and is matching a legitimate, documented pattern - confirm with the asset/account owner before escalating.
- An approved administrator or automation legitimately required and obtained elevated privileges through a documented process.
- A security-testing tool intentionally exercised the privilege-escalation path as part of an approved assessment.
- A legitimate administrator, script, or scheduled task executed the command/binary as part of approved, documented operations.
- A security or monitoring tool itself performs an action that matches this execution pattern by design.

### True Positives

- This technique, part of "Signed Binary Proxy Execution," allows the execution of arbitrary commands or DLLs, often bypassing application whitelisting and potentially User Account Control (UAC).
- An account or process gains privileges it does not normally hold, with no corresponding approval or ticket.
- The elevation is followed by actions normally reserved for administrators.
- The technique used matches a known, documented privilege-escalation exploit or misconfiguration abuse.
- The executing process, command line, or binary has no legitimate reason to run in this context and matches known attacker tradecraft.
- Execution is followed by further suspicious activity (network connections, new files, privilege changes) on the same host.

### True Negatives

- The elevation matches an approved administrative workflow.
- The execution is confirmed to be part of an approved script, deployment, or administrative task.

### False Negatives

- The attacker already holds sufficient privileges from an earlier, undetected compromise, so no escalation event occurs for this detection to catch.
- Escalation is achieved through a legitimate-looking, pre-existing misconfiguration rather than an exploit this detection watches for.
- The payload executes through a technique or LOLBin not yet covered by this detection's specific logic.
- The malicious code runs entirely in memory or is obfuscated enough to avoid matching the detection's pattern.
